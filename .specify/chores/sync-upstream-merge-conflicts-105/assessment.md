## Key finding: both conflicts are disjoint line-level edits, resolved by union

### 1. `packages/agent-core-v2/docs/state-manifest.d.ts` (generated file)

The file is generated by `pnpm gen:state-manifest` and guarded by
`test/state/stateManifest.test.ts` (see `packages/agent-core-v2/AGENTS.md` — "Do not edit by
hand").

- **Fork side adds** 2 state keys from fork-owned features — `fallbackModel.active`
  (`src/session/fallback/state.ts`) and `squeezeModel`
  (`src/agent/fullCompaction/squeezeForkOps.ts`) — plus a `compactionTokenBudget` field
  inside `fullCompaction.tuning`; index count 73 → 75.
- **Upstream side removes** the `tower.base` state key (part of upstream tower refactor
  #4074, "coordinate missions with deterministic orchestration"); index count 73 → 72.
- Only the index-count comment line conflicts textually; the additions/removals auto-merge
  in disjoint regions. Union = take both sides, count **74**.

Resolution strategy: resolve the text conflict as the union, then regenerate the file with
`pnpm gen:state-manifest` on the merged tree and let `stateManifest.test.ts` prove
freshness — the generator is the source of truth, so the hand-resolved conflict text only
needs to be correct enough to parse before regeneration.

### 2. `packages/agent-core-v2/src/features/tower/tools/spawn/spawnTool.ts` (hand-written)

Upstream #4074 restructured `execution()`: the whole spawn flow (rate-limit gate, abort
controller, subagent binding, launch, task registration, agent registration, logging) moved
**inside** the `withBranchLease(...)` callback; `secondaryAlias` does not exist upstream.

- **Fork side** has a single 1-line change on top of the merge-base: passing
  `{ secondaryAlias: this.profile.getSessionModelOverride('secondary') }` as the 4th
  argument of `resolveSubagentBinding(...)` — the fork's secondary-model cascade reaching
  tower-spawned workers/reviewers. This is fork-owned behavior that must be preserved.
- The conflict's origin/master side is the merge-base's **pre-refactor** fragment of that
  `binding` computation, which upstream's restructure deleted/relocated; the upstream side
  of the hunk is empty. The fork's un-refactored fragment is superseded by the auto-merged
  upstream body (which carries the same flow in its new position).

Resolution strategy: take the upstream refactored body (drop the stale fork fragment — it is
a duplicate of the relocated flow), then **re-apply the fork's 1-line `secondaryAlias`
argument** to the `resolveSubagentBinding(...)` call inside the new lease callback. Verified
in the merged tree that the fork API surface survives: `resolveSubagentBinding` accepts
`overrides?: { secondaryAlias?: string }` (`src/session/subagent/configSection.ts:263`) and
`IAgentProfileService.getSessionModelOverride` exists (`src/agent/profile/profile.ts:162`).
